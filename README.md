# Sentienta Bridge

The Sentienta Bridge connects Sentienta agents to OpenClaw and approved local resources.

This public release includes two supported modes:

- **Personal Bridge** for OpenClaw agents and local resources controlled by one Sentienta user.
- **Enterprise Bridge** for OpenClaw agents and local resources controlled by a Sentienta organization.

Slack and GitHub are native Sentienta Connected Services and do not require a bridge. General MCP services and Zapier are not included in this public release.

## Download

Clone the public repository:

```powershell
git clone https://github.com/sentienta-ai/sentienta-bridge.git
cd sentienta-bridge
```

Alternatively, download the repository ZIP from https://github.com/sentienta-ai/sentienta-bridge/archive/refs/heads/main.zip and extract it to a trusted directory.

When upgrading, replace `sentienta_bridge.py`, `sentienta_bridge_v2.py`, and `sentienta_bridge_enterprise.py` together so the shared core and both entry points remain compatible.

## Files

- `sentienta_bridge.py` - shared bridge core and execution logic
- `sentienta_bridge_v2.py` - recommended personal bridge entry point
- `sentienta_bridge_enterprise.py` - headless Enterprise Bridge entry point
- `requirements-enterprise.txt` - Enterprise Bridge dependencies
- `start_sentienta_bridge.ps1` and `start_sentienta_bridge.cmd` - Windows personal-bridge launchers
- `RELEASE_NOTES.md` - current release changes

## Requirements

- Python 3.10 or later (the included convenience launchers are for Windows)
- A Sentienta account
- OpenClaw installed and working on the bridge host when using OpenClaw
- Network access to Sentienta
- For the Enterprise Bridge, `boto3` installed with:

```powershell
python -m pip install -r requirements-enterprise.txt
```

Before starting a bridge, verify OpenClaw itself is available:

```powershell
openclaw status
openclaw agents list
```

## Personal Bridge

1. Start OpenClaw.
2. From the bridge directory, run either `start_sentienta_bridge.cmd` or:

```powershell
python .\sentienta_bridge_v2.py --allow-root . --service local_fs --service openclaw_exec
```

### Experimental native browser prototype

The `codex/native-browser-prototype` branch includes an unreleased, visible native-browser service for governed Workflow testing. It uses a dedicated Chrome profile, accepts only structured `browser.*` commands, permits image attachment only from `--allow-root` paths, and does not publish without a separate approved `browser.submit` call.

```powershell
python .\sentienta_bridge_v2.py --bridge-id desktop_browser --allow-root C:\approved\content --service native_browser
```

### Temporary workflow compatibility shim

During the 2026 CASA production freeze, the unreleased Native Browser Bridge
accepts a narrow `fs.browser.*` alias so existing Core workflow tasks can test
browser preparation without a Core deployment. The Bridge translates allowed
aliases to `browser.*` and reports `native_browser` as the actual service.

This is test-only compatibility behavior. `fs.browser.submit` is deliberately
unsupported. The shim must be removed after Core gains a first-class governed
`browser.*` workflow contract under Desktop Automation.

This prototype is not part of the public production release.

3. The Windows launcher enables Local File Services and OpenClaw and approves the bridge directory as the default Local File Services root. Use a different `--allow-root` only when you intentionally want to expose that trusted folder.
4. The bridge prints a six-digit `PAIRING PASSCODE`. Keep the bridge running.
5. In Sentienta, open **Account Settings > Connected Services > Sentienta Bridge**.
6. Enter the six-digit passcode shown by the bridge and select **Use passcode**.
7. Confirm that the bridge and expected OpenClaw agents appear online, then run a read-only test request.

The passcode is generated by the running bridge and expires after 12 hours by default. It is also written to the local pairing file shown in the bridge output. Do not share it. Restart the bridge to generate a new passcode when pairing expires or must be replaced. One running personal bridge can be connected to only one Sentienta account at a time. Disconnect it before pairing a different account; an attempted cross-account connection is rejected and identifies the account currently connected.

A personal agent participating in a shared Workroom still executes through its owner's paired personal bridge. Another Workroom participant does not gain access to the owner's computer or bridge credentials.

## Enterprise Bridge

The Enterprise Bridge runs on an organization-controlled host. It signs in as an active Sentienta Enterprise Owner or Admin and registers itself automatically with that account's organization. The Enterprise Admin page manages registered bridges; it does not use the personal pairing-passcode flow.

1. Start OpenClaw on the organization-controlled host.
2. Install the Enterprise Bridge dependency:

```powershell
python -m pip install -r requirements-enterprise.txt
```

3. Choose a stable bridge identifier and provide the Sentienta admin password through an environment variable rather than placing it in command history:

```powershell
$env:SENTIENTA_ADMIN_PASSWORD = "your Sentienta password"
python .\sentienta_bridge_enterprise.py --admin-username admin@example.com --bridge-id bridge_acme_01 --service openclaw_exec
```

In Windows Command Prompt, use:

```bat
set SENTIENTA_ADMIN_PASSWORD=your Sentienta password
python sentienta_bridge_enterprise.py --admin-username admin@example.com --bridge-id bridge_acme_01 --service openclaw_exec
```

You may set `SENTIENTA_ADMIN_USERNAME` instead of passing `--admin-username`. The admin account must be an active Owner or Admin of the intended Sentienta organization. Do not use a general platform administrator account unless it is also an active administrator of that organization.

4. Open **Enterprise Admin > Enterprise Services** and confirm that the bridge registered under the intended organization.
5. Confirm that the expected OpenClaw agents are advertised.
6. Add an eligible enterprise agent to a Workroom and run a read-only test request.

Enterprise Bridge session and configuration files are stored under `%USERPROFILE%\.sentienta-bridge` by default. Protect that directory. Re-register or rotate credentials if the host is replaced or compromised.

## Validation

Before relying on either bridge:

1. Confirm it is paired or registered to the intended user or organization.
2. Confirm OpenClaw and the expected agents are online.
3. Run a harmless, read-only request.
4. Verify the result returns to the intended Home conversation or Workroom.
5. For an enterprise agent, verify that organization membership and service policy prevent unauthorized use.

## Security

- Run bridges only on trusted, maintained hosts.
- Protect pairing codes, Sentienta credentials, session files, and bridge configuration.
- Do not put passwords or tokens directly in scripts or source control.
- Give local tools the minimum access needed.
- Keep Python, the bridge, and OpenClaw current.
- Re-pair or re-register after host replacement or suspected compromise.
- Review consequential actions before approval.

## Troubleshooting

Use `--verbose` for diagnostic output.

- **Personal bridge does not appear:** confirm it is still running, port 8765 is available locally, and the passcode has not expired.
- **Enterprise bridge does not register:** confirm the username and password, verify that the account is an active Enterprise Owner/Admin, and check the organization shown in Enterprise Admin.
- **Agent is unavailable:** run `openclaw status` and `openclaw agents list`, then confirm the agent appears in Sentienta.
- **Wrong account or organization:** stop the bridge, remove or securely archive the applicable local session/config files under `.sentienta-bridge`, and start again with the intended identity. Do not reuse credentials from another user or organization.

Slack and GitHub connection problems should be diagnosed in Sentienta Connected Services, not in the bridge.
